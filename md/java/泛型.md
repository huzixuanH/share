+ JAVA推出泛型以前，程序员可以构建一个元素类型为Object的集合，该集合能够存储任意的数据类型对象，而在使用该集合的过程中，需要程序员明确知道存储每个元素的数据类型，否则很容易引发ClassCastException异常。
+ 泛型程序设计（Generic programming) 意味着编写的代码可以被很多不同类型的对象所重用。
+ Java泛型（generics）是JDK 5中引入的一个新特性，泛型提供了编译时类型安全监测机制，该机制允许我们在编译时检测到非法的类型数据结构。
+ 泛型的本质就是参数化类型，也就是所操作的数据类型被指定为一个参数。
+ 不能实例化类型变置，即不能 new T()，new T[];

- - Generic<Integer>[] generics1 = new Generic<Integer>[10]; // ❌
  - Generic<Integer>[] generics2 = (Generic<Integer>[]) new Generic<?>[10]; // **✔**
  - 推荐使用集合：ArrayList<Generic<String>>();

- E 表示集合的元素类型，K 和 V 分别表示关键字与值的类型。T 或 U、S 表示“ 任意类型”。

- 好处

  + 当获取一个值时不用进行强制类型转换。

  + 编译时类型安全监测机制，该机制允许我们在编译时检测到非法的类型数据结构。


# 泛型类
```java
class Generic<T> {
    private T t;

    public T getT() {
        return t;
    }

    public void setT(T t) {
        this.t = t;
    }
}
```

+ 泛型类，如果没有指定具体的数据类型，操作类型是Object
+ 泛型的类型参数只能是类类型，不能是基本数据类型
+ 泛型类型在逻辑上可以看成是多个不同的类型，但实际上都是相同类型
+ 泛型类中的成员方法不能声明为静态的

## 泛型类的派生类
+ 子类也是泛型类，子类和父类的泛型类型要一致   
    - `class ChildGeneric<T> extends Generic<T>`
    - `class ChildGeneric<T,U> extends Generic<T>  `

+ 子类不是泛型类，父类要明确泛型的数据类型
    - `class ChildGeneric extends Generic<String>`

# 泛型接口
```java
public interface Generic<T> {
    void show(T t);
}
```

+ 实现类不是泛型类，接口要明确数据类型
+ 实现类也是泛型类，实现类和接口的泛型类型要一致

# 泛型方法
+ 泛型方法，是在调用方法的时候指明泛型的具体类型。
+ 在方法中出现范型结构，泛型参数与类的泛型无关
+ 可以声明为静态。与是否在泛型类中无关。
+ 泛型方法可以定义在普通类中，也可以定义在泛型类中。



修饰符 <类型> 返回指类类型 方法名（类型 变量名） {}

`public <T> T show(T t) {}`

# **类型通配符**
+ 类型通配符一般是使用"?"代替具体的类型实参。所以，类型通配符是类型实参，而不是类型形参。

```java
/*
使用泛型时：
	class A ectends B {}
	Generic<B> b = new Generic<>();
	Generic<A> a = b; // Error
	Generic<B> 不是 Generic<A> 的子类



类型通配符：<?>
	List<?>：表示元素未知的List，它的的元素可以匹配任何的类型
     	这种带通配符的List仅表示他是各种泛型List的父类，并不能把元素添加到其中，可加null，可读取数据。

类型通配符上限：<? extends 类型>
	List<? extends Number>:表示它是类型Number或者其子类型
类型通配符下限：<? super 类型>
	List<? super Number>: 它表示的类型是Number或者其父类型
 */

import java.util.ArrayList;
import java.util.List;

public class GenericDemo {
    public static void main(String[] args) {
        //类型通配符：<?>
        List<?> list1 = new ArrayList<Object>();
        List<?> list2 = new ArrayList<Number>();
        List<?> list3 = new ArrayList<Integer>();
        System.out.println("--------");

        // 类型通配符上限：<? extends 类型>
        // List<? extends Number> list4 = new ArrayList<Object>(); // Error
        List<? extends Number> list5 = new ArrayList<Integer>();
        List<? extends Number> list6 = new ArrayList<Number>();
        System.out.println("--------");

        //类型通配符下限：<? super 类型>
        //List<? super Number> list7 = new ArrayList<Integer>(); // Error
        List<?super Number> list8 = new ArrayList<Object>();
        List<?super Number> list9 = new ArrayList<Number>();
    }
}
```

# 类型擦除
泛型是Java 1.5版本才引进的概念，在这之前是没有泛型的，但是，泛型代码能够很好地和之前版本的代码兼容。那是因为，泛型信息只存在于代码编译阶段，在进入JVM之前，与泛型相关的信息会被擦除掉，我们称之为--**类型擦除。**

```java
public class Erasure<T> {
    public T key;
    
    public T getKey() {
        return key;
    }
    
    public void setKey(T key) {
        this.key = key;
    }
}

// 类型擦除后
public class Erasure {
    public Object key;
    
    public Object getKey() {
        return key;
    }
    
    public void setKey(Object key) {
        this.key = key;
    }
}
```

```java
public class Erasure<T extends Number> {
    public T key;
    
    public T getKey() {
        return key;
    }
    
    public void setKey(T key) {
        this.key = key;
    }
}

// 类型擦除后
public class Erasure {
    public Number key;
    
    public Number getKey() {
        return key;
    }
    
    public void setKey(Number key) {
        this.key = key;
    }
}
```

```java
public <T extends Number> T getValue(T key) {
    return key;
}


// 类型擦除后
public Number getValue(Number key) {
    return key;
}

```

```java
public interface Info<T> {
    T info(T var);
}

public class InfoImpl implements Info<Integer> {
    @Override
    public Integer info(Integer var) {
        return var;
    }
}

// 类型擦除后
public interface Info {
    Object info(Object var);
}

public class InfoImpl implements Info {
    public Integer info(Integer var) {
        return var;
    }
    // 桥接方法，保持接口和类的实现关系
    @Override
    public Object info(Object var) {
        return info((Integer) var);
    }
}
```
